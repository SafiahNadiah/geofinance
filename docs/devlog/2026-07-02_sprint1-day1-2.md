## 2. Environment Setup

### 2.1 Installed Docker Desktop for Windows

- Downloaded from docker.com, ran installer
- Installer required WSL2 (Windows Subsystem for Linux) — installed via:
  ```powershell
  wsl --install
  ```
  (run as Administrator, followed by a PC restart)
- Confirmed installation:
  ```powershell
  docker --version
  docker compose version
  ```

**Learning:** Docker on Windows doesn't run containers natively — it
runs them inside a lightweight Linux environment (WSL2) that Docker
Desktop manages automatically. No manual interaction with WSL required
after setup.

## 3. Docker Compose Configuration

### 3.1 Files created (via GitHub Copilot, reviewed manually)

- `docker-compose.yml` — 3 services: `postgres` (image `postgis/postgis:16-3.4`), `backend`, `frontend`
- `.env` (from `.env.example`) — `DATABASE_NAME`, `DATABASE_USER`, `DATABASE_PASSWORD`, ports, `JWT_SECRET`

### 3.2 Key config decisions in `docker-compose.yml`

| Setting | Value | Note |
| --- | --- | --- |
| Postgres image | `postgis/postgis:16-3.4` | Postgres 16 with PostGIS 3.4 pre-installed |
| `POSTGRES_DB` | `${DATABASE_NAME:-geofinance}` | Database name is **`geofinance`**, not the default `postgres` — important for later steps |
| Healthcheck | `pg_isready` | Ensures `backend` waits for Postgres to be ready (`depends_on: condition: service_healthy`) |
| Volume | `postgres_data` (named volume) | Persists DB data across `docker compose down` (but not `down -v`) |

## 4. Verification Steps

### 4.1 Config validation (no containers started yet)

```powershell
docker compose config
```
Confirmed YAML resolves correctly with `.env` values substituted.

### 4.2 Start Postgres only

```powershell
docker compose up postgres
```

### 4.3 Confirm container is running

```powershell
docker ps
```
Container `geofinance-postgres` showed status `Up (healthy)`.

### 4.4 First PostGIS check — hit an error

```powershell
docker exec -it geofinance-postgres psql -U postgres -c "SELECT postgis_version();"
```
Result:
```
ERROR:  function postgis_version() does not exist
```

**Root cause:** `psql -U postgres` without `-d <database>` connects to
the default `postgres` database — but `POSTGRES_DB` in this project is
set to `geofinance`, and that's the database where the image
auto-enables the PostGIS extension on first boot. The `postgres`
database itself never had PostGIS enabled.

### 4.5 Fix — connect to the correct database

```powershell
docker exec -it geofinance-postgres psql -U postgres -d geofinance -c "SELECT postgis_version();"
```
Result: returned a valid PostGIS version string. ✅ Confirmed working.

### 4.6 Shut down cleanly

```powershell
docker compose down
```
(Data persists in the `postgres_data` volume for next time — this was
a normal shutdown, not `down -v`.)

## 6. Commands Reference (for future sessions)

```powershell
# Start only the database
docker compose up postgres

# List tables in the geofinance database
docker exec -it geofinance-postgres psql -U postgres -d geofinance -c "\dt"

# Open an interactive psql shell
docker exec -it geofinance-postgres psql -U postgres -d geofinance

# Check PostGIS version
docker exec -it geofinance-postgres psql -U postgres -d geofinance -c "SELECT postgis_version();"

# Full stack up / down
docker compose up
docker compose down          # keeps data volume
docker compose down -v       # wipes data volume (fresh start)
```
