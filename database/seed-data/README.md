# Seed data — GeoFinance

Synthetic dataset for local development, demos, and testing. Generated by
`generate_seed_data.py` (deterministic — `random.seed(42)` — regenerate
any time for identical output).

## ⚠️ Data provenance — read before using anywhere near production

| Data | Real or synthetic? |
| --- | --- |
| Branch **locations** (town/area names, approximate lat/lng) | Real-world *area* coordinates (town centers), used only as realistic anchor points — **not** an actual bank's branch list. |
| Branch names, staff counts, opened dates | Fully synthetic. |
| Customers (names, IC numbers, emails, phone, income) | 100% synthetic, generated with `Faker`. IC numbers follow the *format* `YYMMDD-PB-XXXX` only — they are not valid or real Malaysian ICs. |
| Properties (address, value, geometry) | 100% synthetic. Addresses are Faker-generated strings, not real addresses. |
| Loans (amounts, status, risk score) | 100% synthetic. `risk_score` is computed from a simple illustrative formula (proximity to a synthetic risk zone + income), not a real credit/risk model. |
| Risk zones (flood/landslide polygons) | 100% synthetic illustrative shapes, placed near real place names for demo realism. **Not** sourced from NAHRIM, DID, JPS, or any real hazard map. |

**Do not present this as real hazard, credit, or personal data anywhere —
in a demo, say explicitly it's synthetic.** For a real deployment, replace:
- Risk zones → actual flood/landslide hazard layers (e.g. from `data.gov.my` / NAHRIM, subject to their licensing)
- Branch list → your institution's real branch data
- Customers/loans/properties → your actual (access-controlled, PDPA-compliant) records

## Files (in `output/`)

| File | Rows | Key columns |
| --- | --- | --- |
| `branches.csv` | 18 | `branch_id`, `latitude`, `longitude` |
| `customers.csv` | 2,000 | `customer_id`, `nearest_branch_id`, `home_latitude/longitude` |
| `properties.csv` | 1,200 | `property_id`, `owner_customer_id`, `latitude/longitude` |
| `loans.csv` | 900 | `loan_id`, `customer_id`, `property_id`, `branch_id`, `risk_score`, `risk_tier` |
| `risk_zones.geojson` | 12 | `zone_id`, `hazard_type`, `severity` (Polygon features) |

Relationships: `loans.customer_id → customers.customer_id`,
`loans.property_id → properties.property_id`,
`loans.branch_id → branches.branch_id`,
`properties.owner_customer_id → customers.customer_id`,
`customers.nearest_branch_id → branches.branch_id`.

## Regenerating

```bash
pip install faker numpy pandas
python generate_seed_data.py
```

Edit constants at the top of the script (`N_CUSTOMERS`, `N_PROPERTIES`,
`N_LOANS`, `BRANCH_AREAS`, `RISK_ZONE_CENTERS`) to change volume or
geography.

## Loading into PostgreSQL/PostGIS

```bash
export DATABASE_URL=postgres://postgres:postgres@localhost:5432/geofinance
chmod +x import.sh
./import.sh
```

Requires `psql` and `ogr2ogr` (GDAL) on your machine — both are included
if you install PostGIS via the official Docker image
(`postgis/postgis`), or `brew install gdal` / `apt install gdal-bin` for
`ogr2ogr` locally. See `schema.sql` for table definitions and manual
`\copy` commands if you'd rather run steps individually.
